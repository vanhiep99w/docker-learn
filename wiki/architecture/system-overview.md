# System overview

## Purpose and boundaries

Docker Learn is a content publishing system, not a Docker control plane or interactive lab backend. Its product is a Vietnamese learning path stored in MDX. The application compiles that content into a static website with documentation navigation, client-side search, rendered Mermaid diagrams, Open Graph images, and text interfaces for LLM consumers.

The repository has no database, server-side state, authentication, or runtime API dependency. `next.config.mjs` sets `output: 'export'`, so all supported pages and route-handler outputs must be known at build time and emitted under `out/`.

## Architecture at a glance

```text
Authoring layer
  content/docs/**/*.mdx       lesson content and frontmatter
  content/docs/**/meta.json   section titles and page order
  content/docs/meta.json      curriculum section order
             │
             ▼
Compilation layer
  source.config.ts
    - defines the Fumadocs collection
    - validates standard page/meta schemas
    - retains processed Markdown text
    - transforms Mermaid code fences
             │
             ▼
Generated source layer
  .source/*                   generated by fumadocs-mdx; do not edit
             │
             ▼
Application layer
  src/lib/source.ts           loads the generated collection
  src/app/docs/*              renders the docs tree and pages
  src/app/api/search/*        emits the static search data
  src/app/llms*               emits text/Markdown interfaces
  src/app/og/*                emits page social images
  src/components/*            providers, search UI, MDX, Mermaid
             │
             ▼
Static export
  next build → out/ → Cloudflare Pages
```

## Content source and compilation

`source.config.ts` defines a single `docs` collection rooted at `content/docs`. It uses Fumadocs' standard `pageSchema` for MDX frontmatter and `metaSchema` for navigation metadata. The `includeProcessedMarkdown: true` option is important beyond browser rendering: `src/lib/source.ts#getLLMText` requests each page's processed text for the LLM-facing routes.

The same config registers `remarkMdxMermaid`. A fenced `mermaid` block is therefore converted during MDX processing into the `Mermaid` component registered by `src/components/mdx.tsx`. Changing that chain requires coordinated edits; registering only the remark plugin or only the React component is insufficient.

`fumadocs-mdx` generates TypeScript modules under `.source/`. The `collections/*` alias in `tsconfig.json` points to that generated directory, and `src/lib/source.ts` imports `collections/server`. Both `.source/` and TypeScript build artifacts are ignored by `.gitignore`.

## Application composition

### Root shell

`src/app/layout.tsx` establishes:

- Vietnamese document language (`lang="vi"`);
- Inter font support for Latin and Vietnamese subsets;
- site title and description metadata;
- `metadataBase`, read from `NEXT_PUBLIC_SITE_URL` with `http://localhost:3000` as the local fallback;
- `Provider`, which installs Fumadocs' `RootProvider` and the custom search dialog.

The project constants in `src/lib/shared.ts` centralize the product name, route prefixes, and GitHub repository coordinates. `src/lib/layout.shared.tsx` uses those values for the navigation title and GitHub link. If the repository moves or route prefixes change, update these constants before chasing duplicated URLs elsewhere.

### Documentation shell

`src/app/docs/layout.tsx` passes `source.getPageTree()` into Fumadocs' `DocsLayout`. The tree is derived from the root and section `meta.json` files, so metadata is product behavior rather than optional bookkeeping.

`src/app/docs/[[...slug]]/page.tsx` is the canonical page renderer. It:

1. resolves a page through the Fumadocs source loader;
2. returns `notFound()` for unknown slugs;
3. renders title, description, table of contents, and the compiled MDX body;
4. adds Markdown copy/view controls and a GitHub source link;
5. generates page metadata and Open Graph image references;
6. exposes all page slugs to the static exporter through `generateStaticParams()`.

The page deliberately uses `className="mx-0 max-w-none"`. Git history shows this was added to widen documentation content; do not remove it as incidental styling without checking wide tables, code, and diagrams.

### Home route

`src/app/(home)/page.tsx` redirects `/` to `/docs/bat-dau/`. Git history shows the redirect was narrowed from `/docs/` to the Getting Started section, making the beginner path the intended product entrypoint. Changes to curriculum entry behavior should consider this route and `content/docs/bat-dau/meta.json` together.

## Static deployment model

`next.config.mjs` combines the Fumadocs MDX plugin with:

- `output: 'export'`;
- `reactStrictMode: true`;
- `trailingSlash: true`.

The output is a static `out/` directory. `wrangler.toml` identifies the Cloudflare Pages project as `docker-learn`, points `pages_build_output_dir` at `./out`, and sets `compatibility_date = "2026-01-01"`. There are no Pages Functions or Worker bindings in the current repository.

This architecture means a route that depends on request-time computation, a database, or an unknown dynamic slug cannot simply be added to the current deployment. Either pre-generate it or deliberately revisit the static-export boundary.

## Historical intent

The initial repository commit created the application shell and the entire curriculum skeleton together, establishing content and publisher as one product. Subsequent high-signal changes clarify the intended experience:

- the home page redirects to the beginner section;
- documentation pages use a wider content area;
- Mermaid became an explicit build-time transform plus client renderer;
- curriculum sections are completed in coherent batches rather than page-by-page across unrelated areas.

These patterns favor a guided curriculum with rich technical explanations over a generic reference-site layout.

## Extension points and cautions

| Goal | Primary files | Coupling to preserve |
|---|---|---|
| Add MDX syntax or components | `source.config.ts`, `src/components/mdx.tsx` | Compiler transform and runtime component names must agree |
| Change docs routes | `src/lib/shared.ts`, `src/lib/source.ts`, route files | Static params, links, Markdown URLs, and OG URLs share prefixes |
| Change navigation | `content/docs/meta.json`, section `meta.json` | Metadata order becomes the docs tree |
| Change repository source links | `src/lib/shared.ts` | Layout and per-page GitHub links use the same config |
| Add runtime behavior | `next.config.mjs`, target route | Current static export may not support request-time dependencies |
| Change site metadata | `src/app/layout.tsx` | Production canonical URLs depend on `NEXT_PUBLIC_SITE_URL` |

Before changing architecture, also read [`routes-and-interfaces.md`](routes-and-interfaces.md) and the operational checks in [`../operations/quality-and-troubleshooting.md`](../operations/quality-and-troubleshooting.md).
