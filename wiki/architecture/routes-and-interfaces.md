# Routes and public interfaces

Docker Learn exposes more than rendered HTML. The same Fumadocs source drives browser pages, search data, Markdown endpoints, LLM indexes, and Open Graph images. Treat these outputs as coupled public interfaces when changing slugs or source processing.

## Route inventory

| Route | Implementation | Static-generation behavior | Purpose |
|---|---|---|---|
| `/` | `src/app/(home)/page.tsx` | Redirect emitted by Next.js | Sends users to `/docs/bat-dau/` |
| `/docs/<slug>/` | `src/app/docs/[[...slug]]/page.tsx` | `source.generateParams()` enumerates pages | Main documentation UI |
| `/api/search/` | `src/app/api/search/route.ts` | Fumadocs `staticGET` with `revalidate = false` | Search index consumed by the custom dialog |
| `/llms.txt/` | `src/app/llms.txt/route.ts` | Built from the source page index | Compact LLM-readable page index |
| `/llms-full.txt/` | `src/app/llms-full.txt/route.ts` | Collects processed text for every page | Full-corpus text export |
| `/llms.mdx/docs/<slug>/content.md/` | `src/app/llms.mdx/docs/[[...slug]]/route.ts` | One generated route per source page | Processed Markdown for copy/view actions and agents |
| `/og/docs/<slug>/image.png/` | `src/app/og/docs/[...slug]/route.tsx` | One generated image per source page | 1200×630 Open Graph image |

`trailingSlash: true` in `next.config.mjs` applies to the exported site. Author internal content links with a final slash, for example `/docs/buildkit/buildx/`.

## Documentation pages

The catch-all docs page resolves its slug through `source.getPage`. It uses the page's compiled body and Fumadocs TOC, and it passes `createRelativeLink(source, page)` as the MDX anchor override. That override allows relative links in MDX to resolve in source context, although repository authoring guidance prefers explicit `/docs/.../` routes for predictable static URLs.

The top of each page includes:

- `MarkdownCopyButton`, targeting the per-page processed Markdown route;
- `ViewOptionsPopover`, targeting both processed Markdown and the GitHub source file;
- title and description from frontmatter;
- an Open Graph image URL built by `getPageImage` in `src/lib/source.ts`.

A slug change therefore affects navigation, browser URLs, Markdown URLs, OG image URLs, and links from other lessons.

## Search

Search has a server/build side and a browser side:

1. `src/app/api/search/route.ts` calls `createFromSource(source)` and exports its static `GET` handler.
2. `src/components/search.tsx` creates an in-browser Orama instance and connects it through Fumadocs' `oramaStaticClient`.
3. `src/components/provider.tsx` installs that dialog in `RootProvider`.

Both search configurations currently set Orama's language to `english`, while lesson prose and titles are Vietnamese. This is a known validation watchpoint: do not claim Vietnamese stemming/tokenization quality from configuration alone. Any search change should test accented and unaccented Vietnamese queries against a production-like static build.

Because search is static, newly added pages do not require a manually maintained index, but they do require regenerating the Fumadocs source/build output.

## Machine-readable content

`src/lib/source.ts#getLLMText` formats processed page text as:

```text
# <page title> (<page URL>)

<processed Markdown text>
```

The source collection retains that processed text because `source.config.ts` sets `includeProcessedMarkdown: true`.

The three machine-facing forms serve different scopes:

- `/llms.txt/` is an index generated by Fumadocs' `llms(source).index()`.
- `/llms-full.txt/` resolves every page, waits for all processed texts, and concatenates them.
- per-page `content.md` routes return a single page with `Content-Type: text/markdown`.

The full export grows with every completed lesson. If build time or artifact size becomes a concern, measure this route before changing content processing globally.

## Open Graph images

`src/app/og/docs/[...slug]/route.tsx` uses Fumadocs' default OG renderer with the page title, description, and the `Docker Learn` site name. `generateStaticParams()` iterates every source page, so page additions also add image-generation work to the static build.

The corresponding URL is inserted into page metadata by `src/app/docs/[[...slug]]/page.tsx`. If image route segments change, update `docsImageRoute` and `getPageImage` rather than hard-coding a second path.

## Mermaid lifecycle

Mermaid support crosses build and browser boundaries:

1. Authors add an unindented fenced `mermaid` block in an MDX page.
2. `remarkMdxMermaid` in `source.config.ts` converts the block into a component invocation.
3. `src/components/mdx.tsx` registers that component as `Mermaid`.
4. `src/components/mermaid.tsx` runs client-side, initializes Mermaid with `securityLevel: 'strict'`, selects a light/dark theme, and renders SVG.
5. Render failures display a Vietnamese error caption and the original chart text instead of silently dropping the diagram.

The renderer includes the theme and chart in its state key to avoid showing stale SVG during theme or content changes. Test both themes after changing this component. Since it injects Mermaid-generated SVG with `dangerouslySetInnerHTML`, retain strict Mermaid security settings unless a security review justifies otherwise.

## Change checklist

When adding or changing a route:

1. Confirm it can be statically generated under `output: 'export'`.
2. Provide complete `generateStaticParams()` coverage for dynamic segments.
3. Preserve trailing-slash links.
4. Check whether `src/lib/shared.ts` should own the route prefix.
5. Run `npm run types:check` and `npm run build`.
6. Inspect the corresponding files under `out/`.
7. Test direct navigation, not only client-side navigation.
8. For slug changes, search `content/docs/` for inbound links and verify Markdown/OG interfaces too.
