Docker Desktop với WSL 2 là lựa chọn phổ biến để phát triển Linux containers trên Windows. Điểm dễ nhầm là Ubuntu/Debian WSL distro của bạn **không nhất thiết chạy Docker daemon riêng**. Docker Desktop quản lý Engine trong môi trường WSL của nó rồi cung cấp CLI/socket integration cho các distro được cho phép.

Sau trang này, bạn sẽ cài hoặc cập nhật WSL, bật Docker Desktop WSL 2 backend, xác minh cùng một daemon từ Windows và distro Linux, đồng thời đặt source code ở filesystem phù hợp cho bind mount.

## Kiến trúc cần hình dung

```text
Windows Terminal / PowerShell
        │
        ├── docker.exe ──────────────┐
        │                            │
WSL distro (Ubuntu, Debian, ... )    │ Docker API integration
        │ docker CLI                 │
        │ source code                │
        └────────────────────────────┤
                                     ▼
                         Docker Desktop WSL backend
                           ├── Linux Docker daemon
                           ├── image/container state
                           └── Linux container runtime
```

Distro phát triển và backend Docker Desktop chia sẻ WSL kernel ở mức platform nhưng có distribution/data boundary riêng. Bật integration cho một distro làm `docker` command trong distro đó nói chuyện được với Docker Desktop; nó không biến distro thành một rootful Engine host theo hướng dẫn systemd thông thường.

<Callout type="warn" title="Tránh hai daemon chồng lên nhau">
  Trước khi bật Docker Desktop integration, gỡ hoặc vô hiệu Docker Engine/CLI đã cài trực tiếp trong WSL distro nếu chúng tạo conflict. Đừng chạy một `dockerd` systemd riêng và Docker Desktop cho cùng workflow trừ khi bạn chủ đích quản lý hai context, hai data store và hai network stack.
</Callout>

## Prerequisites

Theo tài liệu Docker Desktop hiện hành, WSL phải từ `2.1.5` trở lên; nên dùng stable mới nhất vì version cũ có thể gây lỗi memory, network, GPU hoặc upgrade. Windows edition/build, RAM, virtualization và licensing requirement cũng thay đổi theo Docker Desktop release, nên kiểm tra system requirements chính thức trước khi cài.

Trong PowerShell hoặc Command Prompt:

```powershell
wsl --version
wsl --status
wsl -l -v
systeminfo.exe
```

Bạn cần quan sát:

- `wsl --version` in được version; nếu không có version detail, có thể đang dùng inbox WSL cũ;
- distro dự định tích hợp có `VERSION` là `2`, không phải `1`;
- hardware virtualization đã bật;
- Windows release còn trong support window của Microsoft/Docker.

Nếu máy do tổ chức quản lý, kiểm tra Docker Desktop subscription, endpoint policy, VPN/proxy và quyền cài application trước.

## Bước 1: cài hoặc cập nhật WSL

Mở PowerShell với quyền Administrator cho thao tác bật feature lần đầu:

```powershell
wsl --install
```

Nếu WSL đã có:

```powershell
wsl --update
wsl --shutdown
```

Restart Windows nếu installer yêu cầu. Sau đó kiểm tra lại:

```powershell
wsl --version
wsl -l -v
```

Đổi một distro đã có sang WSL 2 bằng tên hiển thị chính xác từ `wsl -l -v`:

```powershell
wsl --set-version <DistroName> 2
```

Đặt WSL 2 làm default cho distro mới:

```powershell
wsl --set-default-version 2
```

`<DistroName>` là placeholder, ví dụ tên do `wsl -l -v` trả về. Conversion có thể mất thời gian và cần disk trống; backup dữ liệu distro quan trọng trước.

## Bước 2: cài Docker Desktop

Tải installer từ trang Docker Desktop chính thức hoặc Microsoft Store theo policy tổ chức. Installer hiện có thể cung cấp per-user và all-users mode; capability như Windows containers/Hyper-V phụ thuộc mode và Windows edition.

Trong wizard:

1. Chọn WSL 2 backend nếu mục tiêu là Linux containers.
2. Hoàn thành cài đặt và khởi động Docker Desktop từ Start menu.
3. Chấp nhận license/đăng nhập nếu policy yêu cầu.
4. Vào **Settings → General** và kiểm tra **Use WSL 2 based engine**. Trên hệ thống chỉ hỗ trợ WSL 2, setting có thể được bật mặc định và không hiển thị.
5. Chờ Docker Desktop báo Engine đang running trước khi kiểm tra CLI.

Không dùng một download URL hard-code lâu dài trong automation. Lấy installer, checksum và supported flags từ release notes/official deployment documentation tại thời điểm rollout.

## Bước 3: bật WSL integration

Trong Docker Desktop:

1. Mở **Settings → Resources → WSL Integration**.
2. Bật integration cho đúng distro development.
3. Chọn **Apply**.

Nếu không thấy mục WSL Integration, Docker Desktop có thể đang ở Windows containers mode. Chuyển về **Linux containers** từ Docker menu.

Có thể đổi default WSL distro trong PowerShell:

```powershell
wsl --set-default <DistroName>
```

Không cần bật integration cho mọi distro. Mỗi distro được bật có thêm đường tương tác với Docker Desktop; chỉ cấp cho môi trường thật sự dùng.

## Bước 4: xác minh từ Windows

Mở PowerShell mới:

```powershell
docker context show
docker version
docker info --format 'OSType={{.OSType}} Architecture={{.Architecture}}'
docker run --rm hello-world
```

Kết quả cần có:

- `docker version` có Client và Server;
- server `OSType=linux` khi đang dùng Linux containers;
- `hello-world` pull, chạy và exit thành công.

Docker Desktop tạo context phù hợp theo version/config. Không hard-code tên context; dùng `docker context ls` và đọc endpoint hiện tại.

## Bước 5: xác minh từ WSL distro

Mở shell của distro đã bật integration:

```bash
docker context show
docker version
docker info --format 'OSType={{.OSType}} Architecture={{.Architecture}}'
docker run --rm alpine uname -a
```

Nếu cả Windows và WSL shell trỏ cùng Docker Desktop backend, hai phía sẽ thấy cùng Docker objects trong user/backend boundary tương ứng. Tạo một container đã exit để kiểm tra:

```bash
docker create --name wsl-context-check alpine true
docker container ls --all --filter name=wsl-context-check
docker rm wsl-context-check
```

Trong PowerShell, chạy `docker container ls --all` trong lúc object còn tồn tại để đối chiếu. Nếu không thấy, kiểm tra context và user boundary trước khi kết luận dữ liệu mất.

## Đặt source code đúng filesystem

Với Linux container và bind mount, đặt project trong Linux filesystem của WSL, ví dụ:

```bash
mkdir -p ~/src/demo
cd ~/src/demo
pwd
```

Mount từ Linux path:

```bash
docker run --rm \
  --mount type=bind,src="$PWD",dst=/workspace \
  alpine ls -la /workspace
```

Tránh đặt workload có nhiều file I/O dưới `/mnt/c/...` rồi bind mount vào Linux container. Docker khuyến nghị filesystem Linux vì:

- metadata/file operation thường nhanh hơn;
- Linux `inotify` event phục vụ hot reload đáng tin cậy hơn;
- permission và symlink gần với production Linux hơn.

Bạn vẫn có thể mở project bằng Windows editor qua `\\wsl$\<DistroName>\home\...` hoặc integration của IDE. Đừng chạy cùng repository bằng tool Windows và Linux với line-ending/permission policy mâu thuẫn mà không cấu hình Git/editor.

## Phân biệt ba lớp cấu hình

| Nhu cầu | Nơi cấu hình |
|---|---|
| Docker Desktop backend, CPU/memory/disk, proxy | Docker Desktop Settings hoặc admin settings được hỗ trợ |
| WSL VM resource policy | WSL configuration theo Microsoft documentation |
| Shell/tool trong distro | Dotfiles, package manager và project trong distro |
| Docker daemon option được Desktop expose | Docker Engine/Resources settings của Desktop, không mặc định là `/etc/docker/daemon.json` trên distro |

Đặc biệt, proxy fields đặt trong `daemon.json` của Linux Engine bị Docker Desktop bỏ qua theo Docker documentation; cấu hình proxy qua Desktop settings.

### Kiểm soát memory

WSL 2 cấp phát memory động. Sau build lớn, Linux page cache có thể khiến Windows thấy memory chưa được trả ngay. Docker khuyến nghị giữ WSL cập nhật và cân nhắc `autoMemoryReclaim` trên WSL hỗ trợ tính năng đó. Nếu cần limit CPU/memory/swap cho utility VM, dùng cơ chế WSL/Docker Desktop hiện hành và chạy `wsl --shutdown` sau thay đổi.

Không đặt limit quá thấp chỉ để giảm `vmmem`; build có thể OOM hoặc chậm vì swap. Đo workload thật rồi chọn giới hạn.

## Networking và `localhost`

Published port thường có thể truy cập từ Windows host:

```bash
docker run --name wsl-web --rm -d \
  -p 127.0.0.1:8080:80 nginx:alpine
```

Từ PowerShell:

```powershell
curl.exe --fail http://127.0.0.1:8080/
```

Dọn từ WSL:

```bash
docker stop wsl-web
```

Bind `127.0.0.1` giữ lab ở loopback. Dùng `-p 8080:80` có thể expose rộng hơn tùy platform/config. Với access từ thiết bị khác, VPN hoặc mirrored networking, behavior phụ thuộc WSL và Docker Desktop version; kiểm tra official networking docs thay vì hard-code IP của WSL VM vì IP có thể đổi.

## Security boundary

- WSL hỗ trợ interoperability: Windows có thể truy cập Linux filesystem qua `\\wsl$`, và Linux có thể truy cập drive Windows. Đây không phải strong isolation cho secret trước process Windows cùng user.
- Docker API vẫn là control-plane mạnh. Không mount Docker socket vào container không tin cậy.
- Chỉ bật WSL integration cho distro cần thiết.
- Không lưu credential vào image layer hoặc command history; dùng credential store/secret mechanism phù hợp.
- Nếu threat model cần boundary mạnh hơn shared WSL kernel, đánh giá Hyper-V backend và Docker Desktop security features theo edition/license.

## Troubleshooting theo boundary

### `docker` không tồn tại trong WSL distro

1. Docker Desktop có running không?
2. Distro có WSL version 2 không?
3. Integration đã bật cho đúng tên distro chưa?
4. Shell có được mở lại sau Apply không?
5. Có package Docker cũ che binary/path do Desktop tích hợp không?

Không cài vội `docker.io` trong distro; việc đó có thể tạo một stack thứ hai thay vì sửa integration.

### Client có nhưng không có Server

```bash
docker context ls
docker version
```

Từ Windows:

```powershell
wsl --status
wsl -l -v
```

Restart Docker Desktop trước khi reset dữ liệu. Nếu WSL bị treo sau update, lưu công việc rồi dùng `wsl --shutdown`; thao tác này dừng toàn bộ WSL distro đang chạy.

### Bind mount chậm hoặc hot reload không chạy

Kiểm tra path project:

```bash
pwd
mount | grep '/mnt/c' || true
```

Nếu source nằm dưới `/mnt/c`, clone/move project vào `~/src` trong WSL và chạy toolchain từ WSL shell. Đồng thời kiểm tra application có watch đúng container path và mount không.

### Port không truy cập được

```bash
docker ps --format 'table {{.Names}}\t{{.Ports}}'
docker port <container>
docker logs <container>
```

Phân biệt application chưa listen, port publish sai, container exit, Windows firewall/VPN can thiệp và CLI đang trỏ nhầm context.

### Disk của Docker Desktop tăng lớn

Dùng `docker system df -v` để biết object nào chiếm chỗ trước khi prune. Xóa image/container không tự động làm virtual disk file co lại ngay. Dùng chức năng disk management/cleanup do Docker Desktop version hiện tại cung cấp; backup volume cần giữ trước factory reset.
